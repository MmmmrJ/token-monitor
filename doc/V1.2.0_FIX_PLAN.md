# Token Monitor v1.2.0 发布阻断修复方案

> 当前分支：`codex/v1.2.0-background-monitor`
>
> 目标版本：`v1.2.0`
>
> 计划日期：2026-07-27
>
> 结论：功能主体已落地，但在修复以下阻断项并完成回归前，不创建 `v1.2.0` Tag 或 GitHub Release。

## 1. 测试结论

### 1.1 已验证通过

- `npm test`：现有 4 项前端测试通过。
- `npm run check:versions`：版本一致性检查通过，版本为 `1.2.0`。
- `npm run build`：前端构建通过。
- `cargo fmt --check`：通过。
- `cargo clippy --all-targets -- -D warnings`：通过。
- GitHub Actions Quality workflow：通过。
- 原生应用验证：Codex / Cursor 切换、双环 / 聚焦视图切换、关闭窗口隐藏到托盘、重复启动恢复现有窗口均可工作。

### 1.2 已发现问题

1. 登录时启动的 UI 状态与操作系统真实状态可能不一致；旧版 LaunchAgent 仍可能遗留并启动旧应用副本。
2. 后台刷新协调器虽然合并了并发请求，但每个等待者在请求结束后仍可能重复执行快照、托盘、告警和失败状态副作用。
3. 运行中的设置面板未展示“额度提醒”区块，需确认是否为旧 WebView 资源、构建产物或布局裁切导致，并以全新打包应用验证。
4. 托盘摘要将重置时间直接显示为 ISO 时间戳，不符合桌面组件的倒计时表达。
5. Release workflow 上传了 Windows `.nsis.zip`，但聚合 `latest.json` 时仍选择 Setup EXE；这不符合 Tauri Windows updater 的签名/更新产物要求。
6. GitHub 仓库尚未配置 Tauri 更新签名私钥，应用内更新 Release 当前必须保持阻断。
7. 本机 `cargo test` 有一项重定向测试因沙箱禁止绑定本地监听端口失败；该问题并非断言失败，CI 已完整通过，仍需在可绑定端口的本机或 CI 环境保留验证。

## 2. 修复目标

1. 让后台监测、告警、托盘状态与登录时启动在 macOS / Windows 上具备可预测的真实行为。
2. 确保设置页面可访问、可恢复，并且不出现已删除的 Toast 提示。
3. 让应用内更新仅使用签名、可验证的 Tauri updater 产物。
4. 完成 v1.2.0 的单元、集成、原生 UI 与发布前验证。

## 3. 实施方案

### 3.1 修复登录时启动的真实状态与旧项迁移

涉及 Rust 的 autostart 设置读取、更新和旧项迁移逻辑。

- 每次打开设置和每次切换开关时，均从 `tauri-plugin-autostart` 读取实际启用状态；前端不再仅依赖上一次保存的偏好值。
- 检测并清理旧版 `Codex Usage Monitor` 登录启动项：
  - macOS：安全卸载旧 LaunchAgent，再删除仅属于旧应用的 plist。
  - Windows：清理旧注册表启动项或旧任务，且只处理可识别为本应用的条目。
- 若清理、启用或禁用失败，使用设置区域内的持久内联错误说明；不使用 Toast。
- UI 首次渲染前等待原生状态返回，避免出现“关闭但实际仍启动”的闪烁。
- 增加迁移后验收：重启系统后只有 `Token Monitor` 启动，禁用后不再启动，旧版本残留不再创建第二实例。

### 3.2 让后台刷新协调器真正 single-flight

重构 `src-tauri/src/coordinator.rs` 的并发刷新结束逻辑。

- 以发起本次 refresh 的任务为唯一 owner：只有 owner 负责清理 inflight 标记、更新失败退避、写入最后快照、发射前端事件、更新托盘以及评估提醒。
- 并发调用方只 await 同一个 in-flight 结果并返回，不重复执行后处理。
- 保持现有的 60 秒后台刷新、手动刷新防抖、Provider 分桶缓存与网络失败回退策略。
- 补充单元测试：
  - 多个并发 refresh 仅发生一次 Provider 调用。
  - 同一轮仅发送一次 snapshot / tray / alert 副作用。
  - 失败退避在 owner 完成后准确生效。
  - Codex / Cursor 当前活跃 Provider 与告警目标不会串用。
  - 睡眠、恢复与 Provider 切换期间不会产生重复刷新。

### 3.3 修复并验证额度提醒设置可见性与可访问性

排查 `index.html`、`app.js`、CSS 和当前打包前端资源的版本一致性。

- 确保“额度提醒”区域位于设置面板可滚动内容内，且不会被固定底部、`overflow` 或最小窗口尺寸裁切。
- 保留默认只启用 10% 阈值；20% 与 5% 保持用户主动开启。
- 在中英文下补齐可访问名称、焦点样式和键盘操作；禁用系统通知权限时显示明确的内联说明与重新授权入口。
- 对未提供某个窗口额度的 Provider，不生成该窗口的低额度提醒。
- 用全新 `tauri build` 产物验证设置项可见，排除旧开发 WebView 或旧应用副本造成的假象。

### 3.4 将托盘重置摘要改为人类可读倒计时

更新 `src-tauri/src/tray.rs` 的重置标签格式化函数。

- 使用“`Xd Xh Xm`”格式生成剩余时间；中文显示“`X天 X小时 X分`”，英文显示“`Xd Xh Xm`”。
- 自动省略不足的时间单位：例如只剩 48 分钟显示“48分 / 48m”，不显示“0天 0小时”。
- 已过期或未知重置时间显示本地化的不可用状态，而不回显原始 ISO 字符串。
- 复用前端现有倒计时语义，避免主界面和托盘数值不一致。
- 为分钟、小时、跨天、已过期、非法时间和无值补充 Rust 单元测试。

### 3.5 修复应用内更新 Release 产物

修改 `.github/workflows/release.yml` 的 Windows 聚合及签名检查流程。

- 以 Windows NSIS updater archive（`.nsis.zip`）作为 `latest.json` 的 Windows 下载地址和签名来源，而不是 `Setup.exe`。
- 保留供用户手动下载的 MSI、Setup EXE 和 DMG；只有签名的 updater archive 参与应用内更新。
- 将 `.nsis.zip` 纳入聚合下载与查找条件，显式校验对应 `.sig` 文件存在、非空且与目标文件同名。
- 为 macOS Universal `.app.tar.gz` 同样校验 `.sig`，生成前拒绝任何未签名平台。
- 添加 workflow 级脚本测试：给定 fixture 产物，确认 `latest.json` 的平台 URL 不指向 `.exe`、签名字段完整且版本匹配。
- Release Notes 保留未 Apple 公证 / 未 Windows Authenticode 签名的透明说明，并附安装包 SHA-256。

Tauri 官方 updater 在 Windows 上使用 MSI/NSIS 的更新压缩包和对应签名，不能将普通 Setup EXE 作为 updater artifact。[Tauri Updater 文档](https://v2.tauri.app/plugin/updater/)

### 3.6 配置并保护 Release 签名密钥

在 GitHub 仓库 Secrets 中由维护者配置：

- `TAURI_SIGNING_PRIVATE_KEY`（必需）
- `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`（若生成密钥时设置了密码）

要求：

- 私钥只存在于 GitHub Actions Secret 和维护者安全备份中，不写入仓库、Issue、日志或 Release 附件。
- 将 updater 公钥保留在 `src-tauri/tauri.conf.json`；私钥泄露时必须轮换密钥、更新公钥并提升发布版本。
- 在 Secrets 未配置时，Release workflow 应明确失败，禁止创建带应用内更新元数据的正式 Release。

## 4. 验证与验收

### 4.1 自动化验证

执行：

```bash
npm test
npm run check:versions
npm run build
cargo fmt --check --manifest-path src-tauri/Cargo.toml
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
cargo test --manifest-path src-tauri/Cargo.toml
```

- 若本机仍因沙箱禁止监听端口而无法执行重定向测试，应记录为环境限制，并以 GitHub Actions 的完整通过结果作为补充证据。
- 新增 coordinator、tray duration、autostart 迁移和 release manifest 测试必须全部通过。

### 4.2 原生应用验收

- macOS 和 Windows：关闭窗口隐藏到托盘；托盘打开、刷新、退出均正常；第二实例只恢复现有窗口。
- 标题栏拖动、四边 / 四角缩放、最小 `480 × 300`、28px 圆角透明边缘不回归。
- 双环 / 聚焦切换与 Codex / Cursor 切换不触发伪刷新，不串用缓存。
- 无 Codex 5 小时窗口、仅 Cursor 单侧额度、未登录、过期、离线缓存均正确降级。
- 通知权限未授予、提醒禁用、10% 默认提醒、20% / 5% 手动提醒和免打扰均符合设计。
- 设置面板在中文 / English、最小窗口和展开窗口中均完整可见并支持键盘导航。
- 托盘重置提示为本地化倒计时，且与组件显示一致。

### 4.3 发布验收

- 配置签名 Secret 后，在 GitHub Actions 生成 macOS Universal DMG、Windows x64 MSI / Setup EXE、NSIS updater ZIP 及各自 SHA-256。
- `latest.json` 分别指向签名的 macOS updater archive 与 Windows `.nsis.zip`，所有签名可被应用验证。
- 用上一稳定版本测试“检查更新 / 安装更新”；验证失败时保留当前版本并展示明确错误，不下载或执行未验证内容。
- 只有以上项完成后，合并到 `main`、创建 annotated `v1.2.0` Tag 并发布 GitHub Release。

## 5. 非目标与约束

- 不改变 Codex / Cursor token 的读取边界，不把 token、账户 ID、原始响应或请求日志发送到 WebView、日志、导出或仓库。
- 不抓取浏览器 Cookie，不注入 Codex/Cursor，不写回 `auth.json` 或 Cursor SQLite。
- 不使用 Toast；状态提示保持顶部短条或设置区域内联提示，短条可自动消失。
- 保持 Tauri v2、静态 HTML/CSS/JavaScript 前端、透明无边框窗口与现有本地设置键兼容。
